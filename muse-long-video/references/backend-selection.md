# 出视频方式选择

学习依据：2026-11-16核对的DetailFlow GitHub main（2026.11.14-api-v1）[通道选择](https://github.com/AJbeckliy/detail-flow-V2-Ajie/blob/main/references/backend-selection.md)和[API执行](https://github.com/AJbeckliy/detail-flow-V2-Ajie/blob/main/references/api-execution.md)。这里只借鉴通道选择、私密配置和兼容性门槛，不把图片协议当视频协议，也不继承详情页专有审核和计费展示规则。

选择顺序：本次用户明确指定 > 当前项目记录 > 保存偏好 > 首次询问。不能因为工具里有星幕/ZZAI就默认使用；纯规划、已有视频剪辑、只整理Skill不强制配置生成服务。仅安装时可选“稍后再选”，不启动任何生成端。

首次问题：“这次用星幕画布，还是你自己的API生成视频？”不附服务商菜单。选择API后，用户提供：
1. 自己的API地址和对应文档；地址不要求固定包含`/v1`。
2. 私密配置Key：本机环境变量`MUSE_VIDEO_API_KEY`或宿主安全凭证输入，不在聊天/命令参数中粘贴真实值。
3. 精确视频模型ID。只在有真实只读模型列表时列可选模型，不自行选同名变体。

Agent按文档确认：鉴权方式，提交/上传/状态查询路径，响应格式，时长/分辨率/比例限制，参考图数量/格式/尺寸，图像是身份参考还是首帧，是否输出同期声音。只有文生视频而没有所需参考帧能力时，不可承诺连续片段保脸保场景。

只读检查不上传、不生成、不扣费。没有文档明确的安全检查接口时，说明“暂时无法完成兼容验证”，不发送付费探针。检查成功仅代表鉴权/协议前提满足，实际生成仍需对应授权与真实结果验收。

API模式完全跳过星幕安装、配对Token、MCP配置和画布预检。共享脚本规划、中间帧选择、按帧剪辑、声音与验收规则保持不变。用户选通道不等于允许把Muse换成H3等其他模型。

保存偏好在`CODEX_HOME/muse-long-video.local.json`（未设置时为`~/.codex`），其中只存`backend`、媒体根目录、Python路径和API配置文件路径；项目记录`backend.json`保存本次具体通道。兼容配置存用户私有目录，不在Skill中。地址/模型/协议变化需重新检查；旧任务按提交时的配置恢复，不随新偏好切换。

反馈要具体：协议不支持、参考帧能力未知、Key无效、模型未列出、网络暂时超时、费用阈值阻拦。失败不自动切星幕/换站/换模型，也不临时修改接口适配器。
