# 实测经验与证据边界

整理日期：2026-11-16。本文件只沉淀Muse分段长片方法，不把后来H3单次15秒生成的表现算作Muse能力。

| 实际问题 | 已采用处理 | 边界 |
|---|---|---|
| 背影帧+第二张脸图，续段转身换脸 | 前段先转正脸，再选人景清楚的单帧接续 | 第二图是否被采用未知，不宣布“模型只认第一图” |
| 最后一帧脸很大，后段房间变化 | 对比5、5.5、6秒等候选，选择能看见服装、双手和家具的中景 | 5.5秒是该片结果，不是通用阈值 |
| 前段保留到10秒却从5.5秒状态续 | 前段同步截到选中帧；去掉后段重复首帧（若确实重复） | 接点索引、时间戳与剪辑边界不同 |
| 睡袍变吊带/长裤、钥匙环穿指、杯子悬空 | 衣服分层描述，记录手和道具归属，验收后再续拍 | 不能继承坏帧或宣称多加禁止词就能解决 |
| 正面拥抱变成斜抱/倚靠，台词过早 | 保留通过的前缀，只修结尾并明确接触完成后说话 | 本案例未稳定完成正面拥抱，不能列为成功模板 |
| 等待超时、项目切换后卡片查不到 | 按原项目和任务ID恢复查询，检查真实输出 | 未知不是失败、退款或重跑授权 |
| 133+239帧导出多一帧 | 同fps不再额外fps过滤，音视频分别concat并校验解码帧数 | 包含在脚本回归测试中 |
| 模型、平台和声音处理方式交代不清 | 每次保留model/provider/input/voice_method | 禁止把星幕H3测试叫Muse；来源和审美通过分开 |
| 开头自带口红印，局部擦除伤到衣服和嘴唇 | 将局部修补判为失败，保留原片；用户后来改为亲手背 | 修改音效不修复画面因果；错误修补不交为成品 |

历史有效接续：24fps第132帧，人脸、睡袍、手、电视柜与窗帘可见。`[0,133)+[1,240)=372`帧，15.5秒。用户对人景接续反馈“这段就好很多”，但这不覆盖后续拥抱质量。
